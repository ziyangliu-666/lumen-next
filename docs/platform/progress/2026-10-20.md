## Project Title

Lumen Platform. Lumen is an AI for research. You ask one question; several AI agents share
the work; you see every step and its cost. A lead agent splits the question into tasks and
gives parts to reader agents. Each step, finding and cost goes into a call tree, the record of
the run that the user can open. The budget cap is the most an account spends in a month;
spend above it waits for the owner's approval.

For this module, the team builds the Lumen Platform from the Lumen code. Five services
(identity, project, session, worker, billing) run on Kubernetes behind one gateway. Other apps
use the platform through a public API.

## Summary of Work Done

The five services, the deploy pipeline and the public host were merged and deployed on
20 October. Table 1 lists the tasks.

These terms appear in Table 1. A **turn** is one unit of work for a worker: one agent's work on one
task. **Helm** installs the services on Kubernetes from one package, the chart. The **HPA**
(Horizontal Pod Autoscaler) adds service copies when CPU use rises. **KEDA** (Kubernetes
Event-Driven Autoscaling) adds workers when turns wait in the queues. The pipeline checks the
dependencies (**SCA**), scans the code (**SAST**) and scans the running site (**DAST**).

## Problems Encountered

The team met five problems in this period (Table 3). Figure 5 shows the deploy runs before and
after the fix of the image.

![Figure 5. The last six runs of the deploy workflow, and the jobs of run 39441445313, from the GitHub command line on 21 October 2026. The two failed runs stopped at the image scan. Source: terminal recording of the presentation deck.](figures/shot-pipeline.png){width=11.5}

Table 3. Problems from 7 to 20 October 2026 and what the team did. Source: deploy runs
39439752963 and 39441445313.

| Problem | What the team did |
|---|---|
| Budget for the host. The first plan was one EC2 t3.xlarge (4 vCPU, 16 GB) at about USD 5 a day. | One t3.medium (2 vCPU, 4 GB, 2 GB swap) at about USD 1.3 a day. Every container requests 128 MiB; workers scale from 1 to 4. |
| Image distribution. A container registry is one more service to run and to pay for. | The pipeline builds the image, copies it to the host over SSH and imports it into k3s. The image tag is the commit. |
| The image scan stopped the deploy: 5 critical CVEs, from the Docker engine that the web app's image carries. | A platform image without Docker, patched at build. The next run passed every stage. |
| The public API was not on the host at first: `GET /api/v1/openapi.json` returned 404. | Merged and deployed; then keys, registry, asking, usage, the OpenAPI document and the 429 limit were checked on the host. |
| A worker killed by force: its unacknowledged turns ran again from their start. The question ended, but cost USD 0.08 with 8 findings instead of USD 0.03 with 3. | The fix is an idempotency key for each step, so that a repeated turn does not record a step twice. The project report describes it. |
