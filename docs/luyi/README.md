## Rebuilding

```bash
bash build.sh                                   # design.md -> design.docx -> PDF
cd diagrams && python gen_diagrams.py && cd ..  # only if a figure changed
```

`build.sh` reads `PYTHON`, `DOCX_SKILL` and `SOFFICE` from the environment if the
defaults do not fit. The PDF step is best effort: if LibreOffice is not found the
`.docx` is still built and the script says so. Run it from a normal terminal —
a sandboxed shell may not be able to see `C:\Program Files` at all.

## Conventions this document follows

Taken from the two submissions already accepted for this module — `03a
Analysis-Model-Sequence-and-Class-Diagrams.pdf` and
`06-Order-Statechart-Diagram.docx`:

- Front matter carries a metadata table, an AI-use declaration and a figure list.
- Every diagram is a rendered picture with a numbered caption, never source code
  in a code block.
- Analysis figures use «boundary» / «control» / «entity» and put attributes on
  entity classes only (`03a AM.pdf`); design figures drop the stereotypes except
  «interface» and carry parameter and return types (`04a DM.pdf`).
- Every claim traces to a requirement section — the proposal's `§`, or a
  repository document by name.
- Judgement calls and unresolved questions live in one place (§1.3), not as
  changelog notes scattered through the body.
