子模块职责

每个人负责的子模块，以及预期要提供的功能。上面「按人分工」里点模块名会跳到这里。

陆毅

identity

  • GitHub OAuth 登录、Google OAuth 登录
  • 邮箱 + 密码 注册与登录
  • session 的签发、校验、续期、登出
  • 按角色区分 user / staff，登录后按角色跳转（管理员进后台）
  • 账号信息：改名、改密码、查看已绑定的 GitHub / Google

email

  • 注册后发送邮箱验证邮件
  • 需要用户批准（如高额步骤）时发送通知邮件
  • 邮件模板与发送
彭徐剑

projects

  • 从落地页输入的问题新建项目
  • 项目列表，按状态展示：运行 / 等待用户 / 完成 / 停止
  • 项目卡片的状态机，按 state.live 决定是否轮询刷新
  • 打开项目进入会话

findings

  • 记录 agent 报告的发现 / 结论
  • 在首页和会话里展示 findings 卡片
  • findings 关联到产生它的 task
刘子阳

kernel

  • task 模型：session 的主运行是根 task，每次委派开一个子 task
  • 委派引擎：把任务拆给 worker、并发扇出、限制深度
  • 成本沿子 task 上卷（Composite）
  • 预算内自动运行，在三处检查预算（回合前、扇出时、开窗时）
  • trace：把每一步按顺序记下来

broker

  • WebSocket 服务
  • 事件协议：task.opened / status / cost、step.appended、finding.recorded
  • 订阅 / 退订、多客户端广播
  • 断线重连时补发
李卓阳

worker

  • 在沙箱里跑 agent 的 think → tool → observe 循环
  • 产出 step、findings、花费
  • worker 崩溃后从 trace 重放继续

compute

  • 多 provider：Modal / Docker / none
  • 起容器、跑命令、回传 stdout 和 exitCode
  • none provider 返回可读的失败，而不是 null（Null Object）

storage

  • 项目卷，挂进沙箱
  • 文件读写；save 工具把路径限制在会话目录内
  • 会话里文件面板的列表与内容
  • 用户在会话里插话的排队与落地时机（Command）
贺融

ledger

  • 每笔花费记账（compute 与 models）
  • 按项目、按 task 汇总
  • 月度用量与余额显示

billing

  • Stripe 充值（Checkout）
  • 发票与账单
  • 月度上限（cap）
  • 超额请求升级给用户审批（Chain of Responsibility）

secrets

  • 保管用户的 API key：Modal、搜索、模型、Hugging Face
  • 写入后不回显（write-only）
  • 加密存储

admin

  • 所有账号列表：谁、能做什么、花了多少
  • 按角色识别管理员
  • 紧急停止某个失控账号的运行

Architecture

What runs, and who talks to whom.

LinkHowFor
browser → webHTTPSsign in, projects, findings, file contents
browser ↔ brokerWebSocketthe live event stream
web ↔ PostgresSQLaccounts, projects, sessions, findings, ledger, trace
web → sandboxinternalhand over a message, start or stop a session
worker → brokerinternalone event per step
worker → webinternalfindings, trace steps, spend
worker ↔ volumemounted at ~project files, read and written directly
worker → outsideoutboundsearch, Modal, model providers

Three things to know

The loop
Inside the sandbox the worker runs think → tool → observe → think, many times per turn. Subagents start together and return in whatever order they finish.
The volume
One per project, mounted into whichever sandbox is running. It outlives the sandbox — the sandbox is per session and gets killed when idle.
The trace
Every step, in order, in Postgres. A worker that dies loses nothing: a new one replays it and carries on.
One ruleThe worker never touches Postgres. Anything durable goes out through web. The volume is the only store it holds directly, because it is mounted.
